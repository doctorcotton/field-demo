## 字段捷径介绍

「字段捷径」是多维表格字段级开放能力，支持开发者将 AI 能力、垂直场景应用融入用户的业务系统，降低用户使用门槛，提升渗透率和效率。

字段是多维表格作为数据库产品最基础的能力，覆盖的用户非常广。用户使用字段捷径，一次添加，自动运行，无需额外配置自动化工作流，简单方便。

### 两种实现方式

- **公式版**：将一个多维表格公式封装成字段捷径，使用公式实现功能
- **FaaS 版**：支持编写代码、调用第三方 API，可灵活实现自定义功能

本文档主要介绍 FaaS 版的开发方法。

## 快速开始

### 运行环境

如果项目重度依赖 nodejs 或者资源消耗巨大，可以选择将复杂逻辑部分部署到你的服务器 A，然后仅在字段捷径中放调用服务 A 的代码。

或者在开发阶段，就使用与线上相同的环境配置，这是线上的运行环境：

- **Node.js 版本**：14.21.0
- **服务隔离**：按插件+租户维度隔离，支持动态伸缩容，最大 40 个实例
- **单实例规格配置**：1核1G内存
- **运行超时时间**：15 分钟

#### 一些限制

1. 请求的并发数不超过 400
2. 以下三方库无法在沙箱内运行：
   - axios
   - got
   - bcrypt
   - moment
   - jsdom
   - sharp
   - crypto

### 初始化项目

在命令行执行以下命令克隆项目模板代码：

```bash
git clone https://github.com/Lark-Base-Team/field-demo.git
```

项目目录结构为：

```
├── config.json        // 本地调试授权的配置文件
├── package-lock.json
├── package.json
├── src
│   └── index.ts       // 项目入口文件
└── tsconfig.json
```

#### 其他功能的代码示例

为了方便你了解如何开发一个字段捷径，我们还提供了其他功能的代码示例：

1. [field-demo](https://github.com/Lark-Base-Team/field-demo) 的 `feat-ocr` 分支：展示了一个接收附件字段作为输入，发起 mock API 然后返回发票 Object 字段的插件
2. [field-demo](https://github.com/Lark-Base-Team/field-demo) 的 `feat-attachment` 分支：展示了一个接收文本字段作为输入，解析文本的 URL 然后返回附件字段的插件

### 调试表单UI

#### 第一步：启动本地服务

在克隆下来的项目根目录中执行以下命令启动本地服务：

```bash
# 安装依赖
npm install

# 启动本地服务
npm run start
```

#### 第二步：创建调试字段

1. 基于 [FaaS字段捷径调试模板](https://feishu.feishu.cn/base/DiQXbSLkSaGmwUsHkfJcAscunlh?table=tblwp5TejhYSjeNU&view=vewPbLApNL) 复制副本
2. 点击右侧边栏的「字段捷径调试助手」，或者直接在侧边栏插件市场中搜索"字段捷径调试助手"，然后运行，pin 到侧边栏即可

**在确保本地服务已启动的情况下**，点击打开面板按钮，字段的相关配置（表单 UI、关联字段等信息）便会显示在创建字段的面板上。

以 `feat-ocr` 示例代码为例，选择必填的附件字段后点击保存便能创建一个调试字段。

**注意**：通过【字段捷径调试助手】创建的捷径字段，只会自动生成第一行的值，并且要保证【字段捷径调试助手】和【本地服务】处于运行状态。

#### 第三步：模拟 FaaS 请求

选择需要进行调试的 FaaS 字段，点击**「调试字段」**：

调试插件便会模拟请求 FaaS 的行为，将你的 `execute` 函数执行结果写入多维表格。目前我们仅支持本地模拟请求 FaaS 调试，目前调试模式下的插件只能使用「字段捷径调试助手」触发更新，无法通过自动更新，未来我们还会支持云端调试的方式。

### 发布捷径

在项目目录下执行 `npm run pack`（nodejs 版本 14.21.0 及以上），然后将 `output/output.zip` 文件上传即可。

上线后则需要将你的项目提交到 Github 上，然后提交[多维表格捷径插件表单](https://feishu.feishu.cn/share/base/form/shrcnwTXnFVAbMPOSeaOFwIAnbf)

## config.json 配置详解

`config.json` 是本地调试时的配置文件，**由系统读取，代码不直接读取**。主要用于：

1. **mockData**：模拟用户输入的数据，用于本地调试
2. **authorizations**：模拟授权信息，用于本地调试授权功能
3. **domainList**：域名白名单配置（通常不需要在 config.json 中配置，在代码中通过 `basekit.addDomainList()` 配置）

### 配置结构

```json
{
  "authorizations": [],
  "domainList": [],
  "mockData": {}
}
```

### mockData 配置

`mockData` 用于本地调试时模拟用户输入的数据。

#### 格式要求

- **key 必须与 `formItems` 中的 key 完全匹配**（区分大小写）
- **值的类型必须与 `formItems` 中组件返回的数据类型一致**

#### 示例

假设 `formItems` 中定义了：

```typescript
formItems: [
  {
    key: 'baseUrl',
    label: '问卷基础链接',
    component: FieldComponent.Input,  // Input 返回 string
    // ...
  },
  {
    key: 'account',
    label: '金额',
    component: FieldComponent.FieldSelect,
    props: {
      supportType: [FieldType.Number],  // FieldSelect 返回 number
    },
    // ...
  }
]
```

则 `config.json` 中应配置：

```json
{
  "mockData": {
    "baseUrl": "https://example.com/form/xxx",
    "account": 100
  }
}
```

#### 常见问题

**问题1：字段读取不到（undefined）**

- 检查 `mockData` 中的 key 是否与 `formItems` 中的 key 完全一致（区分大小写）
- 检查字段值的类型是否匹配

**问题2：类型不匹配**

- Input 组件返回 `string`
- FieldSelect 根据字段类型返回对应类型（如 Number 字段返回 `number`）
- SingleSelect 返回 `{label, value}`
- MultipleSelect 返回 `[{label, value}]`

详细的数据类型说明请参考 [开发指南 - 表单组件](./开发指南.md#表单组件详解)。

### authorizations 配置

`authorizations` 用于本地调试时模拟授权信息。详细配置方法请参考 [高级功能 - 授权配置](./高级功能.md#授权配置)。

### domainList 配置

`domainList` 通常不需要在 `config.json` 中配置，域名白名单应在代码中通过 `basekit.addDomainList()` 配置。详细说明请参考 [开发指南 - 请求外部数据](./开发指南.md#请求外部数据)。

## 捷径插件基础结构

捷径主要由 `formItems`、`execute`、`resultType` 3 个主要属性组成，它们描述了插件入参、执行函数和返回结果。

### formItems（输入字段）

`formItems` 描述了捷径的 UI 表单，捷径运行时 `formItems` 的配置值会作为 `execute` 函数的入参。

```typescript
basekit.addField({
  formItems: [
    {
      key: 'attachments',
      label: t('attachmentLabel'),
      component: FieldComponent.FieldSelect,
      props: {
        supportType: [FieldType.Attachment],
      },
      validator: {
        required: true,
      }
    },
  ],
  // ...
});
```

详细说明请参考 [开发指南 - 表单组件详解](./开发指南.md#表单组件详解)。

### resultType（返回结果）

`resultType` 描述了捷径返回字段的类型和属性。

```typescript
basekit.addField({
  resultType: {
    type: FieldType.Object,
    extra: {
      icon: {
        light: 'https://example.svg',
      },
      properties: [
        {
          key: 'id',
          type: FieldType.Text,
          title: 'id',
          hidden: true,
        },
        {
          key: 'url',
          type: FieldType.Text,
          title: t('url'),
          primary: true,
        },
      ],
    },
  },
  // ...
});
```

详细说明请参考 [开发指南 - 返回结果类型详解](./开发指南.md#返回结果类型详解)。

### execute（执行函数）

`execute` 是捷径的运行函数，包含业务逻辑。

```typescript
basekit.addField({
  execute: async (formItemParams, context) => {
    const { attachments } = formItemParams;
    const attachment = attachments?.[0];
    if (attachment) {
      return {
        code: FieldCode.Success,
        data: {
          id: attachment.tmp_url ?? '',
          url: attachment.tmp_url ?? '',
          name: attachment?.name,
          size: attachment?.size,
        },
      };
    }
    return {
      code: FieldCode.Error,
    };
  },
  // ...
});
```

详细说明请参考 [开发指南 - execute 函数详解](./开发指南.md#execute-函数详解)。

## 项目结构

一个标准的字段捷径项目结构如下：

```
├── config.json              // 本地调试配置文件（系统读取，代码不读取）
├── package.json             // 项目依赖配置
├── package-lock.json        // 依赖锁定文件
├── tsconfig.json            // TypeScript 配置
├── src/
│   ├── index.ts            // 项目入口文件
│   └── utils/              // 工具函数目录（可选）
│       ├── logger.ts       // 日志工具
│       └── formula-builder.ts  // 公式构建工具
└── output/                 // 构建输出目录
    └── output.zip         // 打包后的文件
```

### 入口文件示例

```typescript
import { basekit, FieldType, field, FieldComponent, FieldCode } from '@lark-opdev/block-basekit-server-api';
const { t } = field;

// 添加域名白名单（只能调用一次）
basekit.addDomainList(['example.com']);

// 定义字段捷径
basekit.addField({
  // i18n 多语言配置
  i18n: {
    messages: {
      'zh-CN': {
        'name': '字段捷径名称',
        // ...
      },
      'en-US': {
        'name': 'Field Shortcut Name',
        // ...
      },
      'ja-JP': {
        'name': 'フィールドショートカット名',
        // ...
      }
    }
  },
  
  // 输入字段配置
  formItems: [
    // ...
  ],
  
  // 返回结果类型配置
  resultType: {
    // ...
  },
  
  // 执行函数
  execute: async (formItemParams, context) => {
    // ...
  }
});

export default basekit;
```

## ⚠️ 重要提醒

**格式修改后必须重新创建字段**：如果字段的输入输出格式有修改（包括 `formItems` 的 key 改变、`resultType` 类型改变等），必须删除多维表格中已创建的字段捷径，然后重新创建，否则会出现数据格式不匹配、字段读取失败等 bug。

详细说明请参考 [高级功能 - 重要注意事项](./高级功能.md#重要注意事项)。
